# アーキテクチャ

## 依存関係

```text
pages/home → visualization/td4 → circuits/td4/runtime → simulator/td4
                              ↘ circuits/td4/layout / power-layout
pages/modules → 同じ詳細回路・描画・シミュレーター
pages/home → td4/programs → td4/instructions / assembler
scripts/generate-cpu-circuits → circuits/td4/build → generated/*.json
```

本体はworkbenchに依存しません。移植した論理カーネルと配置計算はES ModulesのJavaScriptで保持し、`circuits/td4/runtime.ts` にReact側が使う型付きAPIを定義しています。UI・実行セッション・ルーティングはTypeScriptです。シミュレーターはReact・DOM・言語・実時間から独立しています。

従来のNANDデモとそのTypeScriptランナーは教材用に残しています。TD4はフィードバック、MOSの浮遊状態、階層内で共有するイベントキューを扱うため、`simulator/td4/` の専用ランナーを使用します。

## 回路定義と生成

`circuits/td4/layout.js` がモジュールの固定配置・外部端子・配線経路を定義します。`circuit.js` は各接続を1 bitの端子と配線に変換します。`build/` は再利用する素子回路のテンプレートをCPUの外形へ合わせ、クロック等長化と1.3幅に対応した配置・配線を生成します。

生成結果は9モジュール×3構成の27個のJSONです。電源線の有無は同じMOS定義を共有します。公開する版は1.3のみで、配線幅の選択や0.8版の生成物はありません。生成元と生成物のハッシュをmanifestで検証します。ブラウザには配線探索コードを含めず、構成・モジュール単位の遅延読み込みを使います。

## CPU実行と観察時間

配線の遅延はモデル座標の実長を360描画単位／観察秒で割った値です。各素子は到着イベントで評価され、素子の内部遅延はゼロです。表示倍率・画面幅は配線長や遅延に影響しません。同時刻の到着はまとめて処理します。

全体ブロック表示はMUX・ALU・DFFなどのプリミティブを接続して実行します。他の構成は内部の加算器・ラッチ・NAND・MOS回路も接続して実行し、CPUと内部回路が時刻とイベントキューを共有します。別の命令エミュレーターで表示を駆動しません。命令単位の参照実装はテスト専用です。

詳細CPUのCLOCKは回路全体が安定してから立ち下がりを送ります。クロックパルス中は外部入力を固定します。初期表示とリセットでは安定化した時刻0からクロック待ちになります。

`visualization/td4/session.ts` がCPU実行と再生を管理します。Reactのコンテキストで同じセッションを共有し、プログラム欄はPCの変化、操作欄は公開スナップショットを購読します。SVGの静的図形は構成変更時に構築し、信号の色・波面は回路領域内で更新します。非表示タブでは観察時間を進めません。

- 連続実行は、回路が安定するたびに次のクロックを送ります。
- 再生操作は1つに統一しています。一時停止は新しいクロックと進行中の伝播を即座に止め、再生はその位置から連続実行を再開します。
- 「1命令進める」は入力の伝播を待って1クロックを実行し、伝播完了後に自動で一時停止します。途中のクロックがある場合は、その命令だけを完了します。「信号を細かく見る」では、命令内のイベントや0.1秒単位で進められます。
- 一時停止は伝播途中も含めて観察時間を止めます。
- 次の変化・時間ステップは一時停止して同じキューを進めます。

## 表示の切り替え

全体ブロック・モジュール・NAND・MOS電源線省略・MOS電源線ありの5表示を維持します。初期表示はMOS電源線ありです。全体ブロックのCPU点線枠は、INPUT・OUTPUT・ROMを除く領域を囲う注釈であり、回路や時間に影響しません。独立したCPU表示段階や枠の表示切り替えはありません。

構成が変わる場合は進行中の伝播・命令を完了し、ROM・外部入力・レジスタ値・命令数を引き継ぎます。新しい回路を安定化し、観察時間を0へ戻します。MOSの電源線だけを切り替える場合は同じシミュレーターを保持し、時刻と伝播途中の状態も保ちます。

## プログラムと詳細実験

`td4/programs/` の構造化命令から機械語と表示を生成します。6サンプルはカウントアップ、LEDちかちか、入力→出力、入力を2倍、入力を半分、ラーメンタイマーです。2倍・半分は各8命令で、入力を最初に一度読み、計算後は番地7を繰り返して結果を保持します。サンプル選択でROMを読み込み、CPUをリセットします。編集中のドラフトは実行中のROMに影響せず、「適用してリセット」で反映します。未使用ROM番地は00です。カスタムソースはlocalStorageへ保存し、保存できない環境でも編集できます。

命令一覧の強調はPCの保持値、回路内ROMの強調は配線を経て到着した番地です。両者が伝播途中で異なることがあります。

`/:locale/modules/:moduleId/` はCPUとは独立した実験です。9モジュールで入力・保持・伝播を観察でき、ホームと同じ1.3版の4詳細表示を使います。構成変更時は入力と保持値を引き継ぎます。CPU本体のレジスタを書き換える操作ではありません。

## 翻訳・画面・公開

ホームは短い導入、回路、詳しい説明の順です。PCでは左に折りたたみ可能なプログラム欄、右に回路を置きます。スマートフォンでは回路を先に置き、プログラム欄は初期状態で折りたたみます。

`/ja/`・`/en/` の言語変更はプログラム・表示のクエリを保ち、CPUを作り直しません。ズーム・編集状態も保持します。ページを離れた場合や再読み込みした場合のCPU実行状態の復元は行いません。

Viteビルド後に日英のホーム・記事・詳細実験の入口HTMLを生成します。サーバー側の実行やDBは不要です。`SITE_BASE`によるサブディレクトリ公開に対応します。
