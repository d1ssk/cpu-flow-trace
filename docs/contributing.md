# 回路と記事の追加

## 回路

1. `src/circuits/<module>/` を作成し、回路定義を `circuit.ts`、描画に必要な配置を `layout.ts`、外部向けの API を `index.ts` に置きます。
2. 入出力と内部ノードには安定した ID を付けます。接続・時間・状態は回路側に、翻訳や操作 UI は表示側に置きます。
3. 下位モジュールの回路定義を組み合わせます。ホーム用と記事用のロジックを複製しないでください。
4. 真理値だけでなく、伝播順序・同時到着・短いパルス・初期化など、その回路に必要なテストを追加します。

TD4の回路は `circuits/td4/build/` の生成元を編集し、`npm run generate:cpu` で更新します。生成済みJSONは直接編集しません。CPUと独立したモジュール実験は同じ回路定義・論理カーネルを使います。旧NAND教材のランナーは組合せ回路用です。

## 解説

1. `src/articles/index.ts` に ID・グループ・日英タイトルと概要を登録します。配列の順序が記事番号と前後のナビゲーションを決めます。
2. `npm run build` で記事一覧から日英の `learn/<id>` の入口が自動生成されます。記事の追加時に `scripts/static-routes.mjs` を編集する必要はありません。
3. 共通の `ArticlePage` から表示できます。本文を作る段階で `src/articles/<id>/ja.mdx`・`en.mdx` と MDX のビルド処理を追加します。
4. 操作できる回路は `visualization/` を共有し、説明文と同じページで観察できるようにします。

1記事で1つの仕組みと1つの操作できる回路を扱います。本文は「問い」「操作できる回路」「変化を順に説明」「TD4での役割」の順に構成します。記事内の回路は固定した構成とし、下位回路の説明には前の記事へのリンクを使います。

UI の新しい文言は `i18n/ja.ts` と `i18n/en.ts`、またはTD4専用の `visualization/td4/messages.ts` の日英両方に追加します。英語側のキーは TypeScript が検査します。

## プログラム

`td4/programs/` に `Program` 型のデータを追加し、`index.ts` に登録します。アセンブリは構造化データを正とし、機械語と表示文字列はそこから生成します。C 風コードは説明用で、コンパイルや CPU 実行には使いません。出典を記録し、標準 TD4 の16語に収まることを確認してください。

## 検証と公開

```sh
npm run check:cpu
npm test
npm run build
npm run test:e2e
```

`npm test` は `src/` 内のすべての `*.test.ts`・`*.test.js` を再帰的に実行します。新しいページでは両言語の直接アクセスとリロードも確認してください。公開用の成果物は `dist/` です。
